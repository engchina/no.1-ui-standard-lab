# テンプレート構成のデザイン仕様

## ユーザーの意図

ページテンプレートや再利用可能なブロックは、単にコンポーネントが正しく並んでいるだけでなく、意図をもって設計されたプロダクトのサーフェスとして見えるべきです。明確な読み順、まとまりのある領域、テーマに左右されない強調を確立しつつ、プロダクト固有のコンテンツとアプリケーションのクロームは採用側のプロダクトに委ねます。

## デザイン原則

- **DR1 — レイアウトは目的を伝える。** 構造的な領域、グリッド、積み重ねによって、個々のコンテンツが読まれる前にページの主要タスクが明らかになっていなければなりません（MUST）。
- **DR2 — 視覚的階層が視線を導く。** サイズ、ウェイト、配置によって、ページのコンテキストから主要なコンテンツとアクションへと至る意図的な経路を確立しなければなりません（MUST）。
- **DR3 — 余白と整列が関係性を表す。** 繰り返し現れる端、間隔、グルーピングの階層は、構成全体を通じて一貫していなければなりません（MUST）。
- **DR4 — コンポーネントはアフォーダンスを保つ。** テンプレートは、意図するアクション、ナビゲーション、データ、ステータスの役割に視覚言語が合致するコンポーネントとバリアントを選ばなければなりません（MUST）。
- **DR5 — 色とテーマは階層を保つ。** サーフェスとアクセントの選択は、サポートするすべてのテーマとカラーモードにおいて、意味と強調を維持しなければなりません（MUST）。

## 構造と階層

| 役割               | 目的                                                             | 求められる関係                                                     |
| ------------------ | ---------------------------------------------------------------- | ------------------------------------------------------------------ |
| ページコンテキスト | 利用者が今どこにいて、このサーフェスが何のためにあるかを示す     | 主要タスクと競合することなく、視覚的階層の先頭に立つ               |
| 構造領域           | ナビゲーション、コントロール、コンテンツ、補足情報をグループ化する | 役割に見合ったレイアウト上の境界と余白を用いる                     |
| 主要コンテンツ     | ページの主要なタスクや情報を担う                                 | 最も強い階層を継続的に与えられる                                   |
| 主要アクション     | その場で最も重要な次のステップを提供する                         | アクショングループ内で唯一であり、容易に識別できる状態を保つ       |
| 補足コンテンツ     | 説明、メタデータ、二次的なアクションを加える                     | 階層を平坦にすることなく、利用可能な状態を保つ                     |
| 繰り返し項目       | リスト、グリッド、テーブル、カードのコレクションを構成する       | 現実的なコンテンツのばらつきがあっても、整列とリズムを保つ         |

## 状態の表現

| 状態                   | 求められる表現                                                       | 許容されるバリエーション                                                                         |
| ---------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| コンテンツが充実した状態 | 現実的なコンテンツでも、領域と階層が明確なまま保たれる               | コンテンツの長さやコレクションのサイズは、テンプレートの目的の範囲内で変化してよい               |
| コンテンツが少ない状態 | 空白が構造を崩すことなく、意図的なグルーピングを保つ                 | 任意の補足領域は非表示になってよい                                                               |
| 制約された状態         | 読み順や主要アクションを失うことなく、領域がリフローする             | ナビゲーションや二次的なコンテンツは、各ファミリーの契約に従って移動または折りたたまれてよい     |
| ライトモード／ダークモード | サーフェスの階層、コントラスト、アクセントの意味が損なわれない       | パレットと視覚的な個性はテーマが制御する                                                         |
| インタラクティブ       | より大きな構成の中でも、コンポーネントの状態が識別可能なまま保たれる | コンポーネントは、それぞれのファミリーが所有する表現を維持する                                   |

## レスポンシブと入力方式の挙動

- **DR6 — リフローは読み順を保つ。** レスポンシブな変化においても、ページコンテキスト、主要コンテンツ、補足領域、アクションの関係を維持しなければなりません（MUST）。
- **DR7 — コレクションは恣意的な切り詰めなしに適応する。** 繰り返しコンテンツは、サポートするすべての幅と現実的な項目の長さにおいて一貫性を保つレイアウト戦略を用いなければなりません（MUST）。
- **DR8 — 入力方式が変わってもタスクの階層は同じ。** キーボード、ポインター、タッチのいずれの経路でも、ホバーでしか発見できない仕組みに頼ることなく、同じ主要タスクとアクションに到達できなければなりません（MUST）。

## アクセシビリティの意図

視覚的階層は、セマンティックな読み順およびフォーカス順と一致しているべきです。リフローによって、ラベル、説明、エラー、アクションが、それらが対象とするコンテンツから切り離されてはなりません。テーマの違いがあっても可読性と状態の意味が保たれ、現実的なコンテンツによってアクセシブルでないオーバーフローや切り詰めが生じてはなりません。

セマンティックなマークアップ、コンポーネント API、フォーカス管理、レスポンシブの実装は、コンポーネント、レイアウトファミリー、利用者向けガイダンスが担います。

## 代表的な例

- 情報密度の高いデータページであっても、一目見たときに、明確なタイトル、コントロール領域、主要なデータ領域、アクションの階層がそれぞれ 1 つずつはっきりと示されている。
- カードコレクションが、現実的なタイトルやメタデータ、任意コンテンツの欠落があっても、整列とグルーピングを保っている。
- 狭いレイアウトで補足領域が移動しても、読み順は変わらず、主要アクションも隠れない。

## ビジュアルリファレンス

この初期ドラフトには、規範となるアセットは含まれていません。昇格前に、ページ全体およびブロックの代表例を、ライト、ダーク、ワイド、制約された各状態で `docs/design/assets/template-composition/` 以下に追加する必要があります。

## コンポーネント契約へのリンク

コンポーネント契約へのリンクは定めていません。記載したレイアウトファミリーとの関係はレビュー対象の候補です。利用者側のテンプレートは、引き続き、それらのファミリーが公開するパブリックな契約を用いる責任を負います。

## 決定ログ

この記録は、まだリポジトリのデザイン上の決定として承認されていません。このドラフトは、公開されている Design Conventions wiki から、人が判断する視覚的品質の観点のみを移行したものであり、作成の仕組みや監査の評価は意図的に除外しています。

## 未解決の問い

- **OQ1 — 代表的なテンプレート。** 各構成要件について、どのページテンプレートやブロックを規範的な例とすべきか。
- **OQ2 — プロダクトクロームの境界。** どの構造領域を再利用可能なページテンプレートに含め、どの領域をホストアプリケーション側に委ねるべきか。
- **OQ3 — 根拠。** 主観的な判断を誤解を招くスコアに変えてしまうことなく、スクリーンショットレビューで階層と構成をどのように示すべきか。

## 内容の範囲

このファイルは、テンプレート構成について人が判断する視覚的な意図を定義するものです。必須となる React コンポーネント、生の HTML に関するポリシー、アイコンの組み込み方法、スタイリングの仕組み、モックデータの出典、ドキュメントのメタデータ、行数の目標、監査の評価、利用者向けの手順は定義しません。
